# T-SCHOOL UI/UX Visual Exploration Brief

此文件是目前視覺概念版本的主要指令。目標是先確認美感與體驗方向，再進行嚴格的 Design System、WCAG 與 Material Design 3 校正。

## 1. Exploration priority

依優先順序：

1. 美感與完整的藝術指導
2. T-SCHOOL 品牌獨特性
3. 新穎但合理的互動敘事
4. 有節奏、能引導注意力的動畫
5. 初次使用者的聚焦與理解

暫時不受既有 Material 3 色彩角色、元件外形、固定尺寸、surface、elevation、間距與動畫強度限制。可以重建視覺 token、版面、卡片、按鈕、欄位與動態語言，不必讓畫面看起來像 Google 或一般後台介面。

## 2. Non-negotiable boundaries

- 視覺自由不等於功能自由：不得破壞現有資料、驗證、課程選擇、設定或程式碼產生行為。
- 保持純靜態 HTML/CSS/JavaScript，不新增前端框架或建置流程。
- 不修改同步核心、資料來源、安全防護或 Apps Script 公開函式名稱。
- 絕對不要參考或仿製 `1Campus/` 的視覺與互動。
- 所有文案保持繁體中文、清楚、直接、適合不懂程式的使用者。
- 不以技術名詞展現專業感；使用者不必先理解 Apps Script 才能完成流程。
- 動畫不能阻止操作；`prefers-reduced-motion` 下仍需提供可完成任務的版本。
- 桌面與手機皆不可出現功能中斷或水平頁面溢出。

## 3. Adoptable redesign changes

### Information architecture

- 將桌面左右獨立捲動改為單一、由上往下的敘事路徑。
- 開場先說明工具價值，再帶入設定，不要一次攤開表單與程式碼。
- 將設定拆成循序卡片：來源與日曆、年級與課程、同步與通知、確認、產生與安裝。
- 每一步顯示「目前步驟／總步驟」與簡潔進度回饋。
- 提供清楚的上一個／下一個動作，同時允許使用者回頭修改。
- 將非必要選項收進最後的「進階設定」，維持合理預設值。
- 在產生前提供設定摘要與直接返回對應步驟的修改入口。

### Code and technical content

- 完整程式碼不再占據主要畫面。
- 預設只顯示一小段程式碼預覽，保留資訊透明度。
- 以「複製程式碼」為主要動作，「查看完整程式碼」為次要展開動作。
- 明確告訴使用者不需要閱讀或修改程式碼。
- 安裝教學與程式碼產出放在流程最後，使用短句與明確動詞。

### Hero and brand storytelling

- Hero 必須直接表達「課表正在被轉換成個人行事曆」的核心價值。
- 可用課表格線、時間刻度、課程方塊、同步軌道、日曆事件等真實產品語彙發展視覺。
- 避免常見 AI landing page：不要套用無關漸層光球、科技粒子、空泛數據卡或通用玻璃擬態。
- 開場可使用一個主要動畫，示意課程方塊從課表重新排列進日曆；動畫必須能在數秒內說明用途。
- 提供明確的「開始設定」按鈕與向下引導，不只放沒有文字的箭頭。

### Step cards and motion

- 卡片進入時可使用有節奏的 scroll reveal、遮罩展開、位移或尺寸轉換。
- 完成一步後，用狀態轉場銜接下一步，而不是讓所有卡片同時競爭注意力。
- 進度、選取、驗證與完成狀態應使用同一套動態語言。
- 動畫可以大膽，但集中在少數編排好的關鍵時刻，避免每個元素各自彈跳。

### Contextual cursor experiment

- 桌面 fine-pointer 裝置可加入「原生游標＋情境光圈」。
- 游標靠近開始、下一步、返回、複製、展開時，可改變形狀或顯示簡短動作提示。
- 文字輸入、選取文字、程式碼與一般表單區維持原生游標。
- 不使用全頁 `cursor: none`，不讓游標動畫承擔必要資訊。
- 觸控裝置與 reduced-motion 模式停用此效果。

## 4. Suggested experience flow

1. Hero：理解用途並開始。
2. Step 1：選擇年級並載入課程資料。
3. Step 2：選擇自己的課程與活動。
4. Step 3：設定通知、同步與必要偏好。
5. Step 4：檢查摘要；需要時展開進階設定。
6. Step 5：產生、複製程式碼並依短步驟完成安裝。

實際欄位分組應以目前程式功能為準；不要為符合步數而遺漏功能。

功能與架構限制仍然有效：保持純靜態 HTML/CSS/JavaScript；保留現有設定、資料載入、驗證、課程選擇、程式碼產生與複製功能；不得修改同步核心、安全防護、Apps Script 公開函式或使用者未要求的資料邏輯。可以重構 configurator 的 HTML 結構、CSS 與只為新互動所需的前端 JS，但不能破壞既有行為。

## 6. Deferred strict pass

方向確認後，再進行第二階段：

- 色彩與非文字對比
- 鍵盤焦點與焦點順序
- 操作目標尺寸
- 螢幕閱讀器名稱、角色與狀態
- 200% zoom、320px reflow
- reduced-motion 完整替代
- loading、empty、error、disabled 全狀態
- token 正規化與 Design System 文件重建
