## 正式來源切換

1. 在私人系統完成三年級完整性、差異政策、候選核准及故障通知驗收
2. 將 `schedule-data.js` 的 `NORMALIZED_API_ORIGIN` 設為唯一正式 HTTPS origin，禁止 query、fragment、帳密或路徑；不從設定碼或使用者表單讀取此值
3. 在設定器 CSP 的 `connect-src` 加入同一個明確 origin，更新共用靜態資產版本
4. 執行 smoke、正規化來源與調課 fixture 測試，重新產生母版程式與 manifest
5. 先用測試 Docs 控制臺與隔離的自有 Calendar 完成首次同步、後續調課、暫停、恢復與背景批次驗收，再發布正式設定器與新版程式

目前公告首頁繼續保留；解除公告須等新來源正式驗收，不因本機測試通過自動恢復

## Google Docs 原控制臺更新

只適用於完成上述正式驗收後提供的新版程式

1. 在原 Google Docs 控制臺暫停自動同步，等待已開始的背景工作完成
2. 開啟原文件綁定的 Apps Script 專案，將原 `Code.gs` 另存為本機備份
3. 在同一 Apps Script 專案替換 `Code.gs`；比對 manifest，維持原有8項 OAuth scopes 與 Sheets v4 唯讀服務
4. 不更換 Docs 副本、不重設 Script Properties、不執行首次匯入、不刪除既有 Calendar
5. 回到原文件重新開啟控制臺，確認年級、選課、Calendar、通知偏好與單次排除仍存在
6. 手動同步一次，來源內容不變時應無事件重建，再恢復自動同步

若需退回舊程式，必須保持自動同步停用；舊程式不認識新來源的暫停政策，不能視為安全的自動恢復方式

## 許可與一致性界線

每次同步開始、每個背景批次，以及每筆事件新增、修改與自動刪除前重新取得來源許可；同一筆事件的屬性更新視為一次操作，並檢查有效期限

來源停用不會撤銷已送至 Google 的 API 請求，也無法與 Google Calendar 達成跨服務交易；已完成的寫入會保留，下一筆操作停止

歷史快照不能自行授權同步；回復會產生新 revision 並保持停用，原驗證時間不變

來源尚未設定時仍使用原正式 `/exec` 設定；這只代表尚未切換，不代表原來源已恢復或適合重新開放公開安裝

共用契約可容納每週最多七天；未來 UI 提供週末時，須同步更新目前限定五天的 adapter 與證據驗證、完成測試及人工核准後才能擴充，不把未提供的週末視為空白課表
